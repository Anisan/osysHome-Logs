# Logs - руководство пользователя

## 1. Для чего нужен модуль

`Logs` нужен для просмотра файлов журналов системы через веб-интерфейс администратора.

С его помощью пользователь может:

- видеть список файлов из каталога `logs`;
- открывать один или несколько файлов для просмотра;
- искать нужный файл по имени;
- сортировать файлы по имени, размеру и дате изменения;
- фильтровать записи внутри лога по тексту, уровню и имени модуля;
- менять порядок показа записей по времени;
- скачивать лог целиком;
- удалять ненужные файлы логов;
- быстро открывать `errors.log` через виджет на панели управления.

Модуль ориентирован именно на диагностику и разбор проблем, а не на настройку логирования.

## 2. Где пользователь видит модуль

Модуль открывается в административном интерфейсе `osysHome`.

Обычно пользователь работает с двумя точками входа:

- страница `Logs` в панели администратора;
- виджет `Errors log` на панели управления, если действие `widget` включено и виджет не скрыт.

Если в URL страницы передан параметр `?file=имя_файла`, модуль попытается сразу открыть этот лог. Именно так работает переход из виджета к `errors.log`.

## 3. Что пользователь видит в интерфейсе

Страница делится на две основные части:

- левая колонка со списком файлов логов;
- правая колонка с содержимым выбранных файлов.

### Левая колонка

В левой части находятся:

- заголовок `Logs`;
- кнопка обновления списка файлов;
- строка поиска файла по имени;
- поле сортировки списка файлов;
- список найденных логов.

Для каждого файла показываются:

- имя файла;
- размер;
- дата и время последнего изменения;
- чекбокс для добавления файла в текущий просмотр;
- кнопка удаления файла.

### Правая колонка

В правой части находятся:

- строка фильтрации содержимого;
- выбор порядка сортировки записей по времени;
- фильтр по модулям, если в логе распознаны имена модулей;
- фильтр по уровням логирования;
- один или несколько блоков с открытыми логами.

У каждого открытого файла есть:

- кнопка повторной загрузки содержимого;
- имя файла;
- счётчик загруженных строк и общего числа строк;
- признак частичной загрузки, если открыт не весь файл;
- кнопка скачивания;
- кнопка сворачивания и разворачивания содержимого.

## 4. Работа со списком файлов логов

После открытия страницы модуль запрашивает список файлов из каталога `logs` и сортирует их по выбранному пользователем правилу.

### Поиск файла

Поле `Search filename...` фильтрует список по части имени файла.

Это удобно, если:

- файлов много;
- нужно быстро найти `errors.log`, `app.log` или лог конкретного модуля;
- требуется выделить файлы с похожими именами.

### Сортировка файлов

Список можно сортировать по:

- имени файла по возрастанию и убыванию;
- размеру файла по возрастанию и убыванию;
- дате изменения по возрастанию и убыванию.

Это помогает быстро находить:

- самые свежие логи;
- самые тяжёлые файлы;
- конкретный файл по имени.

### Обновление списка

Кнопка с иконкой обновления перечитывает список логов с сервера.

Её стоит использовать, если:

- в систему были записаны новые файлы;
- размер или дата изменения логов уже изменились;
- пользователь удалил файл и хочет увидеть актуальный список.

## 5. Открытие и просмотр логов

Есть два способа открыть лог:

- нажать на строку файла, чтобы открыть только его;
- отметить чекбокс, чтобы добавить файл к уже открытым логам.

Таким образом модуль поддерживает:

- просмотр одного файла;
- параллельное сравнение нескольких логов.

После выбора файла модуль загружает его содержимое через API и разбирает строки на отдельные записи журнала.

### Как распознаются записи

Интерфейс пытается разобрать строки по шаблону вида:

```text
12:34:56[INFO][ModuleName] Сообщение
```

Для записи обычно выделяются:

- время;
- уровень логирования;
- имя модуля, если оно есть;
- текст сообщения.

Если следующие строки не начинаются с новой log-записи, они считаются продолжением предыдущей. Так в интерфейсе собираются многострочные ошибки, traceback и другие длинные сообщения.

### Многострочные записи

Если сообщение состоит из нескольких строк, по умолчанию оно показывается в сокращённом виде.

Пользователь может:

- нажать на сокращённую строку, чтобы раскрыть запись полностью;
- нажать ещё раз, чтобы свернуть её обратно.

Это особенно полезно для:

- Python traceback;
- длинных диагностических сообщений;
- JSON или текстовых блоков внутри лога.

## 6. Фильтрация и сортировка содержимого

После открытия хотя бы одного файла становятся доступны фильтры содержимого.

### Текстовый фильтр

Поле `Filter...` ищет текст по сообщению записи.

Оно помогает быстро находить:

- конкретную ошибку;
- имя устройства;
- часть команды;
- ключевое слово вроде `timeout`, `MQTT`, `Exception` или `disconnect`.

Кнопка очистки рядом со строкой фильтра сбрасывает:

- текстовый фильтр;
- выбранные уровни;
- выбранные модули.

### Фильтр по уровням

Можно включать и выключать уровни:

- `UNKNOWN`;
- `DEBUG`;
- `INFO`;
- `WARNING`;
- `ERROR`;
- `CRITICAL`.

Если уровни не выбраны, показываются все записи.

Если выбраны один или несколько уровней, остаются только соответствующие им записи.

### Фильтр по модулям

Если модуль смог распознать имена модулей в строках лога, над списком появятся отдельные метки модулей.

Пользователь может оставить только записи:

- одного конкретного модуля;
- нескольких модулей одновременно.

Если после повторной загрузки файла выбранного модуля больше нет в наборе данных, фильтр автоматически очищается от неактуальных значений.

### Порядок по времени

Записи можно сортировать по времени:

- от старых к новым;
- от новых к старым.

Это влияет не только на показ внутри интерфейса, но и на то, какая часть большого файла будет запрошена с сервера:

- при порядке по возрастанию загружается начало файла;
- при порядке по убыванию загружается конец файла.

## 7. Работа с большими файлами

Для крупных логов модуль загружает не весь файл целиком, а только его часть.

Сейчас интерфейс запрашивает до `3000` строк выбранного файла.

Пользователь при этом видит:

- сколько строк загружено;
- сколько строк всего находится в файле;
- предупреждение, что был загружен только фрагмент.

Это сделано для того, чтобы:

- страница не зависала на очень больших логах;
- загрузка была быстрее;
- разбор содержимого оставался удобным.

Если нужен полный лог без усечения, следует использовать скачивание файла.

## 8. Скачивание и удаление логов

### Скачивание

У каждого открытого файла есть кнопка скачивания.

Она передаёт пользователю полный файл лога, даже если в интерфейсе была загружена только часть строк.

Это удобно, когда нужно:

- отправить лог разработчику;
- сохранить архив;
- просмотреть содержимое сторонним инструментом;
- разобрать весь файл без ограничения по строкам.

### Удаление

У каждого файла в списке есть кнопка удаления.

Перед удалением модуль показывает запрос подтверждения. После успешного удаления:

- файл исчезает из списка;
- если он был открыт справа, он закрывается и удаляется из текущего просмотра.

Удаление полезно, когда:

- нужно очистить старые логи;
- файл больше не нужен после диагностики;
- требуется уменьшить объём накопленных журналов.

> [!IMPORTANT]
> Удаление происходит сразу на сервере. Если файл ещё нужен для анализа, сначала скачайте его.

## 9. Виджет ошибок

Модуль поддерживает виджет `Errors log`.

Виджет показывает:

- количество записей в файле `errors.log`;
- цветовую индикацию наличия или отсутствия ошибок;
- кнопку `Open logs` для перехода в модуль.

Если `errors.log` отсутствует, виджет показывает `0`.

При нажатии на кнопку пользователь переходит на страницу `Logs`, где автоматически открывается файл `errors.log`.

### Что именно считает виджет

Виджет считает не все строки файла, а только те строки, которые распознаются как начало отдельной записи журнала.

Это важно, потому что:

- многострочные traceback не раздувают счётчик на каждую строку;
- число в виджете ближе к количеству реальных событий, а не к числу строк в файле.

## 10. Что модуль запоминает между открытиями страницы

Часть параметров сохраняется в браузере пользователя.

Модуль запоминает:

- фильтр по имени файла;
- текстовый фильтр по содержимому;
- сортировку списка файлов;
- порядок сортировки записей по времени.

После повторного открытия страницы эти значения восстанавливаются автоматически.

Это удобно, если пользователь регулярно работает с одними и теми же логами и типовыми фильтрами.

## 11. Ограничения и особенности работы

При использовании модуля важно учитывать несколько особенностей.

### Формат отображения зависит от шаблона строки

Красивое разбиение на время, уровень, модуль и сообщение работает лучше всего для строк, которые соответствуют ожидаемому шаблону логирования.

Если файл использует другой формат, модуль всё равно покажет содержимое, но:

- модуль может не определиться;
- уровень может остаться нераспознанным;
- фильтры по модулям и уровням будут менее полезны.

### Просмотр доступен только администраторам

API модуля защищён проверкой административного доступа. Это относится к:

- получению списка файлов;
- чтению содержимого;
- скачиванию;
- удалению.

### Работа ограничена каталогом `logs`

Модуль читает и удаляет только файлы из системного каталога `logs`.

Имена файлов дополнительно проверяются, поэтому через API нельзя обратиться к произвольному пути на диске.

## 12. Типовые сценарии использования

### Разбор свежей ошибки

1. Откройте `Logs` или нажмите `Open logs` в виджете ошибок.
2. Выберите `errors.log`.
3. Переключите сортировку по времени в режим от новых к старым.
4. При необходимости включите фильтр `ERROR` и `CRITICAL`.
5. Откройте многострочную запись, если нужно увидеть traceback целиком.

### Поиск проблемы в конкретном модуле

1. Откройте лог приложения или нужный файл модуля.
2. Выберите метку нужного модуля в блоке `Filter by modules...`.
3. При необходимости добавьте текстовый фильтр по ключевому слову.
4. Оставьте только нужные уровни, например `WARNING` и `ERROR`.

### Сравнение нескольких файлов

1. В левой колонке отметьте чекбоксами несколько логов.
2. Откройте их параллельно в правой части.
3. Используйте общий текстовый фильтр и сортировку по времени.
4. При необходимости обновляйте каждый открытый лог отдельно.

### Очистка старых логов

1. Отсортируйте файлы по размеру или дате изменения.
2. Скачайте те файлы, которые нужно сохранить.
3. Удалите ненужные файлы через кнопку корзины.
4. Обновите список, чтобы убедиться, что каталог очищен.

## 13. Краткий итог

`Logs` — это рабочий инструмент администратора для повседневной диагностики системы.

Он объединяет в одном интерфейсе:

- список и метаданные файлов логов;
- просмотр и разбор записей;
- фильтрацию по содержимому, уровню и модулю;
- работу с большими файлами;
- скачивание и удаление;
- быстрый вход в `errors.log` через виджет.

## 14. Новые функции интерфейса

### Режим строк (`Line mode`)

В правой части блока фильтров добавлен переключатель `Line mode`:

- `Word wrap` — длинные строки переносятся и остаются в пределах блока;
- `One line` — строка показывается в одну линию с обрезкой по ширине.

Режим применяется как к обычным, так и к многострочным сообщениям.

### Полноэкранный режим содержимого

В заголовке `Content` добавлена кнопка полноэкранного режима.

При включении режима:

- левая колонка со списком файлов скрывается;
- остается только область содержимого (фильтры и строки логов).

### Выход из полноэкранного режима по `Esc`

В полноэкранном режиме можно нажать `Esc`, чтобы быстро вернуться к обычному виду страницы.

### Что сохраняется между открытиями

Выбранный `Line mode` сохраняется в `localStorage` и автоматически восстанавливается при повторном открытии страницы.
